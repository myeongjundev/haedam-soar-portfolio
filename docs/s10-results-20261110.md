## 원인과 수정

1. Docker `internal` 망이 bridge 프레임 중 다른 대역 목적지를 버렸습니다(`DOCKER-INTERNAL`). Docker bridge가 프레임을 되돌려 보내 게스트 MAC이 Docker 쪽으로 학습됐습니다. pfSense 시리얼 셸은 입력을 삼키고 줄 길이 제한이 있었습니다. → `7d39d2a`, `5faa543`.
2. Docker 기본 주소 풀이 다른 프로젝트의 정지된 망으로 가득 찼습니다. → Graylog backend 서브넷을 설정값으로 고정.
3. Graylog 6.1에서 MATCH_INPUT 번호가 다르고, 팀 파이프라인 stage가 요약 형식이었고, 처리 순서 때문에 스트림 파이프라인이 실행되지 않았습니다. → `s10_lab.configure`에서 맞춤.
4. 팀 pfSense 도구의 `applied_verified`는 "차단이 존재함"이라는 뜻이라, 해제가 성공하면 false가 됩니다. 원복 흐름은 이를 상태 불일치로 판단해 기록 전에 중단했습니다. → unblock은 재조회 결과(config·table·rule 없음)로 판정(`d37287c`).
