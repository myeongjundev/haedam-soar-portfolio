## 3. 구성도와 연결 방식

```text
attacker 203.0.113.22 ─┐                                   ┌─ portal 172.30.94.10:5000
normal   203.0.113.12 ─┤ pf-wan 203.0.113.0/24 (internal)  │ pf-lan 172.30.94.0/24 (internal)
                       └─ em0 203.0.113.1 [pfSense CE VM] em1 172.30.94.1 ─┤
                          (QEMU in container "pfsense": br-wan/br-lan ↔ tap)  └─ controller 172.30.94.100 ─SSH→ haedam-pf-response
```

- **실제 트래픽**: 클라이언트는 LAN 대역으로 가는 경로를 pfSense WAN으로 잡습니다(`ip route`). 포털의 돌아오는 경로는 `portal-route` 사이드카가 pfSense LAN으로 잡습니다. 두 망 모두 internal이라 Docker 게이트웨이(.254)를 통해 바깥으로 나가지 않습니다.
- **pfSense VM**: `pfsense` 컨테이너가 Docker 인터페이스를 bridge와 tap에 연결하고, 자기 주소(.253)는 지웁니다. 게스트 NIC은 e1000(em0 WAN, em1 LAN)입니다. 화면과 키는 QEMU monitor(`screendump`, `sendkey`), 콘솔은 시리얼 소켓으로 다룹니다. `config.xml`은 FAT 전송 디스크 `/vm/xfer.img`(게스트에서는 `vtbd1`)로 주고받습니다.
- **P04 조치**: 컨트롤러가 SSH 강제 명령으로 팀 도구를 실행합니다. 키는 `from="172.30.94.100"`로 묶이고, 다른 명령은 실행하지 않습니다. 비밀번호 로그인과 WebGUI는 사용하지 않습니다.
- **S10 계획(미구현)**:
  - 탐지: 포털 GELF와 pfSense syslog UDP가 Graylog로 들어갑니다(`pfsense` 스트림, `infra/graylog/pipelines/pfsense-parse.txt`). Graylog의 `lab/s8s10/graylog/s10-three-layer.json`은 같은 src_ip의 web-scan, login-bruteforce, pfsense-block을 15분 안에 `card(rule)>2`로 묶습니다.
  - 대응: n8n `haedam-32` 웹훅이 티켓을 먼저 기록한 뒤, 포털 차단과 `haedam-14` SSH pfSense 차단을 실행합니다.
  - 원복: `haedam-50`이 승인을 받아 두 조치를 해제합니다.
  - 아직 정하지 않은 것: Graylog·n8n·티켓 저장소를 `pf-lan`에 붙일지, 별도 망을 만들지.

## 5. 실행 순서

```powershell
py -3.12 tools/pf_lab.py init --iso <ISO 경로>
ssh-keygen -q -t ed25519 -N "" -C haedam-pf-controller -f .local/pf/ssh/controller
py -3.12 tools/build_pfsense_bundle.py --out .local/pf/bundle
py -3.12 .local/pf/bundle/install_bundle.py --verify
docker ps --format "{{.Names}}" > .local/pf/running-before.txt   # 시작 목록 기록. 다른 실측 중이면 기다립니다
py -3.12 tools/pf_lab.py up pfsense
py -3.12 tools/pf_lab.py screen          # .local/pf/screen.png를 보고 keys/type으로 설치기 진행
```

이후 순서는 다음과 같습니다(미실행).

1. UFS 설치를 마치고 `pf_lab.py installed`로 디스크 부팅으로 바꿉니다.
2. 콘솔 메뉴 8(셸)에서 `mount_msdosfs /dev/vtbd1 /mnt`로 전송 디스크를 붙이고 기본 `config.xml`을 복사합니다. 해제 후 `xfer-get`으로 꺼냅니다.
3. `pf_config.py`로 고쳐 `xfer-put`으로 넣고, `/cf/conf/config.xml`에 복사한 뒤 재부팅합니다.
4. 시리얼 셸로 번들을 설치합니다(`install_bundle.py --install`).
5. pfSense 호스트 키로 `known_hosts`를 만듭니다.
6. `pf_lab.py up`으로 나머지 서비스를 띄우고 `pf_verify.py`를 실행합니다.
7. 컨테이너를 정지하고 기존 목록을 복원합니다.
