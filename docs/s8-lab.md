# S8 개인 Docker 실측

2026-11-09 최종 시험은 통과했습니다. [개인 실측 결과·수치·화면](s8-results.md)을 확인합니다.

## 설치

Docker Desktop/Engine + Compose v2, Python 3.12가 필요합니다. 도구는 Python 표준 라이브러리만 사용합니다. Windows 저장소 루트에서 실행합니다. Linux는 `py -3.12`를 `python3`으로 바꿉니다.

```powershell
py -3.12 tools/s8_lab.py init
py -3.12 tools/s8_lab.py up
py -3.12 tools/s8_lab.py configure
py -3.12 tools/s8_lab.py status
py -3.12 tools/s8_verify.py
```

`init`은 `.env`·`.env.soc`·`.env.s8`의 빈 값을 생성하고 기존 비밀값을 유지합니다. `.env.s8`은 S8 포트와 키를 추가하는 로컬 파일입니다. 기존 개인 P01/P02 포털이 15000을 사용 중이면 해당 개인 프로젝트를 먼저 정지하거나 `.env.s8`의 `PORTAL_PORT`를 비어 있는 값으로 바꿉니다. 다른 프로젝트의 볼륨·컨테이너는 삭제하지 않습니다.

프로젝트 이름은 **`haedam-s8-live`**입니다. 학원 컨테이너와 분리된 볼륨을 만듭니다. `172.30.88.0/24`와 `172.30.89.0/29`가 다른 Docker/VPN 네트워크와 겹치면 먼저 배치를 조정해야 합니다. 이 버전의 대응 허용 IP는 워크플로와 함께 고정되어 있으므로 Compose 주소만 임의로 바꾸지 않습니다.

| 화면/서비스 | 기본 접속 |
| --- | --- |
| React·Flask 포털 | `http://127.0.0.1:15000` |
| Graylog | `http://127.0.0.1:19100` — admin / 로컬 `.env.soc`의 관리자 암호 |
| n8n | `http://127.0.0.1:15700` — 최초 UI 접근에서 소유자 설정 |
| 티켓 대시보드 | `http://127.0.0.1:18100` |
| GELF TCP | 루프백 22300 → 컨테이너 12201 |
| MySQL·Mongo·OpenSearch·티켓 쓰기 API | Compose 내부 전용 |

`configure`가 GELF 입력, 포털 스트림, 정확한 알림 URL 허용 목록, 인증 알림, S8 집계 규칙을 만듭니다. `haedam-10/11/12/14/32/40/50`만 가져와 하위 의존성까지 게시하고 n8n을 재시작합니다. ID 없는 오프라인 후보와 다른 케이스·무인증 시험 웹훅은 가져오지 않습니다. 처음 설정한 탐지 규칙은 정지 상태이며 검증 도구가 실행 시 활성화합니다.

원본은 `infra/n8n/workflows/`, 개인 배포본은 `infra/n8n/portfolio-s8/`입니다. 생성 원본을 고친 뒤 아래 명령으로 내보내기를 갱신합니다. 수동 JSON 수정은 다음 생성 때 덮어써집니다.

```powershell
py -3.12 tools/build_s8_workflows.py
py -3.12 tools/build_s8_workflows.py --check
py -3.12 -m unittest discover -s tests -p test_s8_workflows.py -v
```

## 실측 순서

1. 인증 없음·틀린 키·탐지 키로 원복 시도 거부를 확인합니다.
2. 일반 클라이언트 4개의 접속 200을 확인합니다. `.21`은 조치 대상, `.22`는 정상 대조, `.23`은 스캔만, `.24`는 로그인 실패만 발생시킵니다.
3. 실제 포털 HTTP 404와 별도 IP의 실제 CSRF 세션을 사용한 로그인 실패 401을 보냅니다. 40초 동안 교차 IP 오탐·단일 신호 탐지가 없는지 확인합니다.
4. `.21`에서 실제 로그인 실패를 추가해 Graylog → 인증된 n8n → 티켓 → 포털 IP 차단을 기다립니다. 이벤트 ID와 티켓을 연결하고 `.21` 403 `IP_BLOCKED`, `.22` 200을 대조합니다.
5. 탐지를 정지하고 같은 이벤트를 동시 재전송해 중복 티켓·추가 차단 요청이 없는지 확인합니다. 잘못된 티켓 ID의 원복을 거부합니다.
6. 독립 관찰 결과를 운영자 키로 보고해 티켓 `verified`를 확인합니다. **개인 티켓 저장소만 잠시 중지**해 실패 응답과 추가 조치 없음, 복구 후 같은 이벤트 재시도를 확인합니다.
7. 같은 티켓의 승인 원복 후 `restored`, 공격·정상 모두 200, 중복 원복·과거 이벤트 재전송의 추가 조치 없음을 확인합니다.

실패하면 규칙을 정지하고 현재 티켓의 원복을 시도합니다. 실패와 정리 결과를 별도 기록하므로 정리 성공이 시나리오 성공을 뜻하지 않습니다. 증거는 `.local/s8/S8-*.json`이며 키·쿠키·비밀번호는 저장하지 않습니다. 전체 시험에는 보통 수 분이 필요합니다.

같은 랩에서 재시험할 때는 **마지막 공격 입력부터 15분**을 기다립니다. 남은 입력을 새 실측으로 착각하지 않도록 도구가 이전 창의 로그를 확인해 거부합니다. 원복 후에도 탐지는 정지 상태로 둡니다. 컨테이너와 데이터는 검토용으로 남깁니다.

```powershell
py -3.12 tools/s8_lab.py stop
```

이 명령은 개인 S8 컨테이너만 정지하며 볼륨은 보존합니다. 다음 시작은 `up`입니다. 원복·재시도 본문과 실패 의미는 [S8 계약](s8-contract.md)을 따릅니다.

장애 복구 후 같은 이벤트 재시도와 담당자 원복은 아래 도구로 수행할 수 있습니다. ID는 실제 Graylog 이벤트·티켓에서 확인합니다. 키를 터미널 명령이나 이력에 넣지 않습니다. 재시도는 최근 30분의 해당 랩 이벤트만 허용합니다.

```powershell
py -3.12 tools/s8_control.py replay --event-id <실제-Graylog-이벤트-ID>
py -3.12 tools/s8_control.py release --ticket-id <실제-티켓-ID>
```

## 검토에서 수정한 항목과 남은 범위

| 발견 사항 | S8 개인 배포 처리 |
| --- | --- |
| 원래 PC 주소·스트림 자리표시자·빈 알림 | 내부 DNS, 실제 생성 ID, 인증 알림을 초기화 도구로 연결 |
| 전체 JSON import 실패·비활성 하위 호출 | 설치 대상을 7개로 제한하고 의존성까지 게시 |
| 포털 키/CIDR 누락, 키 혼용 | 대응망의 n8n 한 IP와 별도 포털·티켓 자격증명 |
| 실패도 HTTP 200 | 실패·보류를 4xx/5xx로 반환하고 실측 도구가 본문도 검사 |
| 원복·효과 보고 인증 없음 | 운영자 전용 키, 대상·티켓 회차 일치 검사 |
| 원문 키가 실행 기록에 남음 | 저장 끄기 + 2.39.5의 지연 삭제 대신 즉시 삭제 경로 적용, DB 검사와 가린 별도 증적 |
| 입력 도구의 팀 대상 고정 | Compose 내부 실제 출발지 4개를 쓰는 개인 S8 검증 도구 |
| S4 순서 설명, S7/Wazuh, S10/pfSense, S12 기준선 | 이번 배포에서 활성화하지 않음. 개별 환경·실측 후 진행 |
| Graylog 6.1/Mongo 6.0의 수명 종료 | 팀 재현 버전 유지. 버전 업그레이드·호환성 시험은 후속 작업 |

Docker/WSL 메모리 6GB 제한 아래 기존 학원 관제 스택과 개인 스택을 함께 실행하는 과정에서 Docker API 500·WSL 시간 초과가 관찰되었습니다. 전체 혼합 구성의 안정적 상시 실행을 검증한 것은 아닙니다. 기존 스택이 있으면 소유자와 사용 상황을 확인한 뒤 개인 시험과 번갈아 실행합니다. 엔진 장애 시에는 실측을 통과 처리하지 않고 복구·자원 배치를 먼저 확인합니다.
