pfSense는 FreeBSD 기반입니다. 공식 설치 경로는 ISO로 VM을 만드는 방식입니다. 한 PC에서 Compose와 pfSense CE VM을 함께 운영하는 구성을 우선 설계하고, 과제의 컨테이너 문구에 이 구성이 허용되는지 강사님 확인이 필요합니다. [Netgate 가상화 문서](https://docs.netgate.com/pfsense/en/latest/virtualization/)

P01·P02의 확인 결과는 [11/9 작업일지](../work-log/members/myeongjundev/2026-11-09.md)에 있습니다. [개인 관제 Docker 설치](docker-soc.md)에서 포트와 콘텐츠 팩 검사 순서를 확인할 수 있습니다.

H1은 팀원의 시청 업무 보안 제안을 채택한 개인 추가 사례이며 기존 여섯 S 시나리오의 검증을 대체하지 않습니다. H2는 기존 404 접근 제어를 유지하며 내부 감사 이벤트를 추가하는 방향, H3/H4는 복원 이력·권한 회수 정책을 보완한 뒤 진행합니다. 당장 남은 필수 인프라는 P03 Wazuh/S7와 P04 개인 pfSense/S10입니다. 이 PC의 Docker/WSL에는 `/dev/kvm`이 없고 기존 VMware pfSense는 실행 중이므로 팀원 문서의 KVM 가능 결과를 우리 환경에 적용하지 않습니다.

각 실행은 동일 실행 ID로 입력·이벤트·워크플로·티켓을 연결합니다. 테스트 명령, 탐지·대응·원복 시각, 건수, 공격/정상 출발지의 결과와 가린 캡처를 남깁니다. 검사용 1~2개는 S8·S10을 우선 준비합니다. [팀 시나리오 설명](https://github.com/NoBugs-Aleph/aleph-soar-public/blob/main/docs/scenarios.md)

- 팀의 11/6 S8 리허설 기록에는 입력 09:45:54 → 탐지 09:46:16 → 포털 차단 09:46:17과 같은 출발지 403·비교 출발지 200·원복 후 양쪽 200이 있습니다. 팀 환경에서의 사례이며 개인 S8 실행 결과는 위 표에서 별도로 관리합니다.
