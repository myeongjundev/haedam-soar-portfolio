S7 init은 인증서 생성용 컨테이너를 실행하므로 이번에는 호출하지 않았습니다. P04/S10의 ISO/VM 설치도 실행하지 않았습니다. S7·P04/S10 Compose의 이전 정적 검사와 실제 결과는 [11/10 점검](installation-audit-20261110.md), [S7 결과](s7-auto-results.md), [P04/S10 결과](s10-results-20261110.md)에 있으며 이번 실행의 검사 수에 더하지 않습니다.

실행 명령은 [설치 안내의 개발 검사](installation-guide.md#개발-검사-환경)를 따랐고, SQLite 위치를 위 값으로 명시했습니다. 새로운 clone과 `.local` 번들·로그는 비공개로 보존했습니다. 테스트가 남긴 상태는 기존 Docker 볼륨에 적용되지 않습니다.

## 발견하고 수정한 문서 문제

| 문제 | 영향 | 수정 |
| --- | --- | --- |
| README가 main만 안내 | 최신 S4/S12 결과·PPT r7 누락 | 최신 후보 브랜치와 #30→#31 병합 후 main 사용을 구분 |
| 설치 안내의 S1/S4/S12/P04·S10 선택 경로 누락 | 어떤 문서와 환경 파일을 쓸지 불명확 | 랩 선택·환경 파일 표와 S12 생성기 검사 추가 |
| 포털·DB 제목 변경 후 앵커 미갱신 | 관제 설치 문서에서 준비 위치로 이동하지 못함 | installation-guide·docker-soc의 README 앵커 수정 |
| 제출 자료가 r5·S12 미실측 상태 | 최신 결과와 제출 문안 불일치 | [11/11 제출 후보](submission-readiness-20261111.md) 작성, 이전 기록에 최신 링크 |
| 이력서 문안에 S10 진행 중, S1/S4/S12 누락 | 실제 개인 기여·검증 범위 누락 | 실측과 실패 해결·원복·한계를 근거별로 반영 |

수정은 문서이며 앱·대응 코드는 변경하지 않았습니다. 최종 파일 경로·PowerShell 문법·비밀정보 검사는 작업일지에 기록합니다. 새 clone 전체 기동은 [제출 후보의 실행 순서](submission-readiness-20261111.md#남은-설치-검증과-실행-순서)로 이어갑니다. 기존 환경을 중지할 수 있다는 새 권한을 이 문서에서 추정하지 않습니다.

점검 시 호스트 총 메모리 15.85GiB·가용 약 2.55GiB, Docker 한도 약 5.79GiB였습니다. 기존 `haedam-s12-lab` 9개 컨테이너가 정지 상태로 남아 있습니다. **새 clone만으로 Docker 프로젝트·볼륨이 분리되지 않습니다.** 같은 프로젝트 이름으로 up하면 기존 컨테이너·볼륨을 재사용/교체할 수 있으므로 실행하지 않았습니다. 기존 환경 유지 조건에서는 별도 PC를 사용하고, 현재 PC의 재사용·새 프로젝트 생성은 별도 실행 범위로 다룹니다.
