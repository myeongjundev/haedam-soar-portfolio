## 오프라인 사용

저장소 루트에서 다음 명령을 실행합니다. Python 3.12 이상 표준 라이브러리만 사용하며 Docker가 없어도 실행됩니다.

```powershell
py -3.12 tools/s1_lab.py check
py -3.12 tools/s1_lab.py plan --run-id prep20261110 --profile boundary8
py -3.12 tools/s1_lab.py plan --run-id prep20261110 --profile trigger9
py -3.12 tools/s1_lab.py init
py -3.12 tools/s1_client.py --settings .local/s1/settings.json --run-id prep20261110 --profile trigger9
```

마지막 명령도 `--execute`가 없어 계획만 출력합니다. `init`은 이 worktree의 새 `.local/s1`에만 파일을 만듭니다. 재실행은 기존 폴더가 있으면 거부하므로 기존 키를 바꾸지 않습니다. 새 계획은 `--settings <JSON>`과 `--output .local/<새 이름>`을 사용합니다. 생성물·키·원시 입력 증적은 Git에서 제외됩니다. Windows의 `chmod`는 ACL 전체를 보장하지 않으므로 개인 계정만 접근하는 작업 폴더를 사용합니다.

주소·포트는 중앙 설정의 **배치 후보**입니다. 현재 실행 중인 Docker·VM과 충돌하는지 확인하지 않았습니다. 네 개 망은 서로 겹치지 않도록 검사하지만 기존 외부 망과의 충돌 확인은 기동 전 별도입니다. `execution_enabled:false`가 초기값입니다.

## 생성되는 파일과 연결 범위

- `settings.json`: 실제 입력기가 읽는 설정 스냅숏.
- `lab.env`: DB·관제·포털 대응·탐지·운영자용 새 난수 키와 설정 포트. 기존 `.env`, `.env.soc`, `.env.pf`에서 값을 가져오지 않습니다.
- `compose.s1.json`: 기존 `compose.yaml`·`compose.soc.yaml` 뒤에 적용하는 추가 구성. 개인 클라이언트망, 응답망, 기본망, Graylog 저장망에 각각 설정한 CIDR을 사용합니다. 공격·정상 컨테이너는 클라이언트망만 연결하고 n8n의 응답망 주소만 포털 대응 API에 허용합니다. 제어판·Wazuh·pfSense를 포함하지 않습니다.
- `graylog-definition.template.json`: 팀 S1 규칙의 사용자+출발지/401/30분/9회 기준을 유지하고 개인 공격 출발지로 제한한 **미연결 템플릿**. 스트림·알림 ID는 빈 목록이며 가져오거나 예약하지 않았습니다.
- `bundle.json`: 향후 Compose 명령의 인자 배열, 프로세스 환경에서 제거할 충돌 키 이름, 미구현 연결 목록. 명령을 실행하는 도구가 아닙니다.
- `runs/`: 향후 입력 결과·중지 파일·입력 잠금. 비밀 키 파일은 클라이언트에 마운트하지 않습니다.

모든 서비스·볼륨은 `bundle.json`의 Compose 프로젝트를 사용해야 합니다. `docker compose`를 직접 실행하기 전 호스트의 동일 환경변수가 `lab.env`보다 우선하지 않도록 기록된 키를 **자식 프로세스 환경에서만** 제거해야 합니다. 현재 단계에는 기동/정지/초기화용 Docker 실행기가 없고 Compose 병합·기동도 아직 검증하지 않았습니다.

## 입력 동작과 증적

| 프로필 | 입력 | 기대와 제한 |
| --- | --- | --- |
| `boundary8` | 최초 health 1회, CSRF 조회+실패 로그인 8회 | 최대 HTTP 17회, 기본 간격 100초, 첫~마지막 로그인 최소 700초. Graylog의 마지막 401 수신 이후 1,860초 무탐지는 별도 관찰 |
| `trigger9` | 최초 health 1회, CSRF 조회+실패 로그인 9회 | 최대 HTTP 19회, 기본 간격 100초, 첫~마지막 로그인 최소 800초. 실제 탐지·티켓·차단을 따로 대조 |
| `normal` | 정상 출발지의 health 1회 | 서비스 응답 대조만 수행. 정상 계정 로그인 성공을 의미하지 않음 |

같은 run ID라도 경계/탐지 프로필의 합성 username을 분리합니다. `zz_s1_b_…`와 `zz_s1_t_…`는 설정 접두어로 생성하며 비밀번호는 실행 메모리에서 난수로 만듭니다. 새 회원 가입이나 계정 변경은 하지 않습니다. 로그에서는 실제 포털 소켓 출발지와 생성된 username을 대조합니다. 실행 전 해당 탐지 키의 지난 30분 입력과 남아 있는 조치가 없는지 확인해야 합니다.

실행 기능은 Linux Docker 클라이언트 안에서 `execution_enabled:true`, 프로젝트 표시 일치, `--execute`가 모두 필요합니다. 시작 전 소켓을 설정 IP에 바인딩하고 실제 로컬/원격 IP를 확인합니다. 환경 프록시·DNS·리다이렉트·X-Forwarded-For를 사용하지 않습니다. 401 `INVALID_CREDENTIALS`만 정상 시험 입력으로 세며 403·429·200·302·통신 오류는 재시도 없이 중단합니다.

`runs/STOP`(파일 이름은 설정 가능)을 만들면 다음 HTTP 요청 전에 또는 대기 중 약 1초 이내에 중단합니다. 진행 중 HTTP 요청은 설정 timeout까지 걸릴 수 있습니다. 공격 입력은 `input.lock`으로 하나만 실행합니다. 강제 종료로 잠금이 남았다면 실행 프로세스 종료와 부분 증적을 확인한 뒤 수동 처리합니다. 같은 run ID/프로필의 결과 파일은 덮어쓰지 않습니다.

실행 증적은 설정/도구 해시, 실제 출발지, 상태 코드, 요청 시각·소요 시간과 401 건수만 저장합니다. 비밀번호·CSRF·쿠키·원문 응답·예외 메시지는 기록하지 않습니다. `input_complete`는 입력 완료일 뿐입니다. 탐지 시간은 클라이언트 종료 시각으로 계산하지 않고 Graylog 원천 수신·조건 충족 시각으로 확인해야 합니다.
