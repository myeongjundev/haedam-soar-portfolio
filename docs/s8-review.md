## 첫 행동

기존 Claude 작업 폴더의 변경을 확인한 뒤 개인 GitHub에서 PR HEAD를 가져와 별도 `claude/s8-review` 브랜치로 검토합니다. Codex 브랜치에 바로 쓰지 않습니다. `gh pr list --state open`으로 실제 PR 번호와 의존 관계를 확인합니다.

1. 빈 볼륨에서 설치·게시·실측 재현 또는 보존한 데이터의 읽기 확인 중 어떤 검증을 했는지 명시합니다. 읽기 확인으로 새 설치를 통과 처리하지 않습니다.
2. 실제 404·CSRF 로그인 실패 401 → Graylog 이벤트 → 티켓의 실행 ID → 공격 403·정상 200 → `verified` → `restored`와 양쪽 200을 대조합니다.
3. 재현됐던 조치 후 목록 조회 403은 `haedam-12`의 Code URL뿐 아니라 HTTP 노드의 고정 URL까지 `portal-response`로 바꿨는지 확인합니다.
4. 정상 키를 가진 공격 클라이언트와 위조 XFF가 포털 대응 API를 우회하지 못하는지 확인합니다. 원복 키와 탐지 키의 권한을 섞지 않습니다.
5. 저장소 장애의 503과 같은 이벤트 재시도, 동시 중복, 오래된 티켓 원복·과거 이벤트 재전송을 재현합니다. 소유권 경쟁·조치 성공 직후 기록 장애 등 이번 개인 실측에서 다루지 않은 조건은 별도 시험으로 표시합니다.
6. n8n 저장 끄기만으로 남았던 soft-deleted payload와 현재 설정의 차이를 확인합니다. 비밀값 대신 키 포함 행 수만 기록합니다. 다른 n8n 버전에서는 즉시 삭제 경로를 재검증합니다.

실패를 발견하면 `[Claude] 검토 HEAD / 명령 / 예상 / 실제 / 최초 실패 지점 / 최소 수정 / 재검증` 형식으로 해당 개인 PR에 코멘트를 남깁니다. 독립 수정이 필요하면 Claude 초안 PR을 열어 의존 PR을 연결합니다. Codex의 검사와 동일 작성자 검사라는 점을 구분하고, 실제로 독립 검토하지 않은 부분을 승인했다고 쓰지 않습니다.
