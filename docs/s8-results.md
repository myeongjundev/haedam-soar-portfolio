Graylog 알림은 정확한 조건 충족 시각을 본문에 채우지 않으므로 티켓 `condition_met_at`은 null이고 대시보드 MTTD는 미측정으로 표시됩니다. 3.828초는 검증 JSON이 실제 원천 이벤트로 별도 계산한 값입니다. 화면의 `D PC` 안내는 반입한 팀 대시보드 문구이며 이번 개인 Graylog 주소는 `http://127.0.0.1:19100`입니다.

## 실패에서 수정한 내용

1. **포털 조치 후 목록 조회 403:** Code 노드의 조치 주소는 대응망으로 바뀌었지만 HTTP 조회 노드의 고정 주소가 남아 있었습니다. 조회까지 `portal-response`로 통일했습니다. 첫 시험은 차단됐어도 적용 확인을 통과시키지 않았고, 수정 후 같은 티켓 원복으로 `restored`와 양쪽 200을 확인했습니다.
2. **n8n 저장 끄기 후에도 키 포함 자료 잔류:** 두 번째 시험은 실제 원복까지 통과했지만 DB 감사에서 실패했습니다. 해당 버전은 기본 pruning을 켜 두면 저장하지 않는 실행도 먼저 soft-delete했습니다. 저장 끄기와 즉시 삭제 경로를 함께 적용하고, 새 볼륨의 세 번째 전체 시험에서 잔류 payload 0을 확인했습니다.
3. **중복 관제 스택 자원 문제:** 6GB WSL에서 기존 스택과 동시에 실행하던 중 Docker API 500·WSL 시간 초과가 발생했습니다. 사용자 승인으로 Docker/WSL을 재시작하고, 두 스택을 번갈아 실행했습니다. `up`에 저메모리·다른 컨테이너 동시 실행 사전 검사를 추가했습니다. 원인을 OOM으로 단정하지는 않습니다.

로컬 실패 기록은 `.local/s8/`에 보존했습니다. 최종 검증은 실패 기록을 고쳐 통과로 만든 것이 아니라 새 볼륨에서 별도로 실행했습니다.
