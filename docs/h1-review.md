## 처음 확인할 것

1. PR HEAD와 증적 source_sha256을 대조합니다. H1 새 볼륨 재현은 기존 S8/학원 스택과 번갈아 수행하고, 기존 실행 목록을 복구합니다.
2. `python -m pytest tests -q`, H1 생성물 `--check`, 백엔드 `tools/check_mysql.py`를 확인합니다. 특히 사용자 행 잠금 전 이미 열린 세션의 MySQL snapshot 회귀 시험을 봅니다.
3. 실제 가입·로그인·민원 4건에서는 무탐지, 5번째 성공 등록 뒤 제한이 적용되는지 확인합니다. 정상 계정의 이벤트와 섞어 계산하지 않아야 합니다.
4. 작성 429를 조회/로그인 실패로 혼동하지 않습니다. 동일 IP 다른 시민 작성 201과 제한 계정의 다른 IP 작성 429를 대조합니다.
5. 탐지 키로 원복 불가, 다른 티켓 해제 불가, 해제한 티켓 재제한 불가, 중복·티켓 저장소 장애 때 추가 조치 없음, 최종 티켓 restored·활성 소유권 0을 확인합니다.
6. 조치 직후 티켓 기록 실패, 해제 직후 기록 실패 등 부분 실패 복구는 추가로 독립 재현할 가치가 있습니다. 현재 자동 시험은 조치 전 저장소 장애를 검증합니다. 단일 n8n 인스턴스 밖 동시 실행이나 실제 시민 정상 기준선은 검증 범위에 없습니다.

HTTP 효과는 실행기에서 독립 확인합니다. 현재 티켓의 `verified_at`과 `condition_met_at`은 null이며 대시보드 MTTD는 미측정입니다. 이를 채웠다고 표시하지 않습니다. n8n의 로컬 티켓 표시 외 Discord 외부 발송은 없습니다.

PR 코멘트 형식: `[Claude] 검토 HEAD / 재현 명령 / 예상 / 실제 / 최초 실패 지점 / 최소 수정 / 재검증`. 검토를 실제로 실행하기 전에는 승인이나 독립 검토 완료로 기록하지 않습니다. 사용자가 최종 병합합니다.
