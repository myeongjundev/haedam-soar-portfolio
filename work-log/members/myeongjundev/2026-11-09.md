## P02 관제 Docker 구성과 전달 검증

- 브랜치 `codex/docker-soc-bootstrap`에서 `compose.soc.yaml`을 추가했습니다. 포털·MySQL에 Graylog 6.1.16, MongoDB 6.0.28, OpenSearch 2.5.0, n8n 2.39.5, 티켓 저장소를 붙였습니다. MySQL, 관제 데이터, n8n과 티켓의 SQLite 파일은 프로젝트별 볼륨으로 분리합니다.
- Windows Docker Desktop에서 두 개의 격리 프로젝트로 빈 볼륨을 만들고 각각 7개 서비스 healthy를 확인했습니다. 기존 수업 컨테이너는 별도 포트에서 계속 실행했습니다. 관제 비밀값은 Git에서 제외한 `.env.soc`로 분리했습니다.
- 포털의 없는 경로 요청 404가 Graylog에 `source:"haedam-portal"`, `rule:"web-scan"`으로 수집됐습니다. n8n 컨테이너에서 티켓 API를 키 없이 호출해 401을 받았고, 티켓 서비스 내부에서 해당 키를 사용한 조회는 200이었습니다.
- 첫 합성 검증은 스트림과 이벤트 생성까지 갔으나 Graylog가 미등록 URL 전달을 차단했습니다. 허용 목록을 유지하고 개인 n8n 웹훅 주소를 Exact match로 등록한 뒤 같은 이벤트 ID에 대한 n8n 성공 실행을 확인했습니다.
- [스모크 콘텐츠 팩](../../../infra/graylog/content-packs/haedam-soc-smoke.json)을 두 번째 빈 Graylog에 설치했습니다. [설치 안내](../../../docs/docker-soc.md)의 PowerShell 입력으로 표식·정상 로그 2건을 전송했습니다. 표식 `p02cc4614af91d6`만 스모크 스트림에 들어갔고, Graylog 이벤트 `01M6YVXBDB7JVT6G5BNCHANAPX`와 n8n 실행 1번 `success`를 대조했습니다.
- 이 검증은 실제 포털 로그 수집과 합성 탐지·전달 범위입니다. 운영 규칙의 차단, 티켓 기록, 알림, 원복 및 개인 Wazuh·pfSense 연동은 후속 실측으로 남겼습니다.
