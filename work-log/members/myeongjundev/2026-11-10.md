## 제어판 HTTP 연결 오류 수정과 S1 메모리 실행 순서

- 작업 ID PANEL-HTTP, 김명준·Codex. PR #21 `2b2fb60` 기준 별도 `codex/panel-http-preflight` worktree. 기존 Docker·VM·실행 중 제어판은 변경하지 않았습니다. 수정된 서버는 임시 loopback 서버에서만 검증했습니다.
- 원인 재현: 본문 도착 전 인증 오류로 POST를 거절하고 연결을 완전히 닫으면 늦게 도착하는 본문과 종료가 경합했습니다. 헤더/본문을 나눈 실제 TCP 테스트에서 본문 전 조기 종료, 반복 POST 테스트에서 기존 WinError 10053을 각각 재현했습니다(수정 전 새 검사 2개 실패). 요청 재시도나 오류 무시로 검사를 통과시키지 않았습니다.
- 수정: 403/404/415/413 및 잘못된 Content-Length 거절은 HTTP 응답을 먼저 보내고 송신 측만 닫은 뒤 제한된 본문을 버립니다. 크기 상한·절대 deadline으로 종료하며, 요청을 해석하거나 작업으로 접수하지 않습니다. 모든 응답에 Connection: close를 명시합니다. 근거는 [RFC 9112 §9.6](https://www.rfc-editor.org/rfc/rfc9112.html#section-9.6)입니다.
- 중앙 설정 `infra/panel-settings.json`에 `http_max_body_bytes=2048`, `http_drain_timeout_seconds=1`을 두고 범위를 검증합니다. 별도 PANEL_CONFIG_FILE에는 다음 시작 전에 두 키가 필요합니다. 기존 로컬 설정을 자동 수정하지 않았습니다. 브라우저 합성 fixture도 중앙 제한값을 읽도록 맞췄습니다.
- 제어판 **23 passed**: 지연 본문, 40회 반복 거절, 본문 미전송/느린 전송/크기 상한/peer 종료, authenticated 400/404/413/415, 기존 인증·CSRF·정상 202 유지, 잘못된 제한값 거절. 크기 상한 검사는 2초 deadline 전에 종료되는 것까지 확인했습니다. 잘못된 요청으로 생성된 작업 0개입니다.
- 전체 호스트 **131 passed·57 subtests passed**, S1 워크플로 4개·Graylog 사양 1개 생성물 일치. 과거 실패한 인증 HTTP 검사와 40회 거절 검사를 추가 3회 반복해 모두 통과했습니다. 최종 테스트의 크기 상한 대조 보완 뒤 제어판 23개 재통과. 기존 PR #21의 미확정 HTTP 실패는 이 수정으로 해소했으며 Claude 독립 승인으로 표시하지 않습니다.
- 읽기 전용 재확인: 기존 7개 컨테이너 모두 실행 중, Docker 약 4.37/5.79GiB, Windows 가용 2.40/15.85GiB. [S1 메모리 실행 순서](../../../docs/s1-memory-sequence.md)에 별도 호스트 경로, 허용 후 기존 Graylog/Wazuh 순차 정지 후보, 단계별 설치·원복·기존 자원 재개 확인을 기록했습니다. 메모리 상향·WSL 재시작·VM 중지·볼륨 삭제는 수행하지 않았습니다.
